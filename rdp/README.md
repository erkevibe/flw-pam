# Windows RDP с согласованием и записью

Экспериментальный локальный стенд Guacamole 1.6.0 / PostgreSQL 16. Отдельные пользователи запрашивают и согласуют доступ; согласование выдаёт настоящее право Guacamole на отдельное RDP-подключение. Отзыв удаляет право и завершает соответствующий туннель.

**Не готово для эксплуатации:** при остановленном обработчике истечения срока право может сохраняться; стартовая очистка не блокирует вход на шлюз автоматически. Это два подтверждённых дефекта безопасности. SSO/MFA, минимальные права служебной учётной записи и защищённый архив записей ещё не реализованы.

## Запуск

Нужны Linux, Python 3.11+, Docker с Compose, свободный порт 18080 и доверенный локальный оператор с UID 1000 — он совпадает с пользователем guacd, читающим закрытое хранилище сертификатов. Из корня репозитория:

```sh
python3 -B rdp/bootstrap.py prepare
env -u COMPOSE_PROJECT_NAME -u POSTGRES_IMAGE -u POSTGRES_PASSWORD \
  docker compose --env-file rdp/.local/private.env -f rdp/compose.yaml up -d
python3 -B rdp/bootstrap.py provision
python3 -B rdp/pam_rdp.py status
```

Подготовка создаёт случайные пароли и фиксирует фактические образы в `rdp/.local/bom.json`. Provision меняет стандартный пароль администратора, создаёт `requester`, `approver`, `outsider` и служебного пользователя. Повторный provision аннулирует текущие заявки и права. Файлы `.local/` приватны и исключены из Git; не публикуйте вывод окружения контейнеров или `compose config`.

Откройте [локальный Guacamole](http://127.0.0.1:18080/guacamole/). Для входа используйте данные `rdp/.local/requester.json`. До согласования подключений нет. Прежний SSH-стенд запускается отдельно на порту 8080.

## Подключение Windows

Windows должна быть доступна из контейнера guacd, принимать RDP/NLA и разрешать вход тестовой учётной записи. Создайте `rdp/.local/windows-target.json`, принадлежащий оператору, с правами 0600. Ровно семь полей:

| Поле | Значение |
|---|---|
| `hostname` | Адрес или DNS-имя тестовой Windows |
| `port` | Целое число, обычно 3389 |
| `username` | Пользователь Windows |
| `domain` | Домен или пустая строка |
| `password` | Пароль Windows |
| `cert_fingerprint` | `sha256:` и 64 шестнадцатеричных символа сертификата |
| `certificate_trust` | Краткое описание происхождения доверенного отпечатка |

Отпечаток должен быть предварительно проверен оператором. Затем установите привязку сертификата:

```sh
python3 -B rdp/trust_init.py --accept-first-observed-lab-pin
```

Команда получает сертификат через TLS без входа в Windows, сравнивает его с указанным отпечатком и записывает закрытое хранилище `known_hosts2`. Несовпадение не заменяет существующее доверие. Флаг подтверждает лабораторную модель доверия; первое наблюдение сертификата само по себе не удостоверяет машину независимо.

В Guacamole отпечаток преобразуется в формат `sha256:aa:bb:…`, необходимый FreeRDP 2.11.7. NLA включена, `ignore-cert` и автоматическое доверие первому сертификату выключены. Нативные отпечатки и `known_hosts` дополняют доверие CA, поэтому это не универсальная политика «только один pin». Перед сменой цели выполните очистку, не изменяйте настройки активных заявок.

Без файла Windows стенд использует недоступный placeholder: можно проверять API, но вход в Windows невозможен.

## Запрос, согласование и отзыв

Запустите обработчик до новых заявок; каждый его запуск сначала аннулирует старые права:

```sh
python3 -B rdp/pam_rdp.py reconcile --watch --interval 2 \
  --credentials-file rdp/.local/approver.json
```

В другом терминале:

```sh
python3 -B rdp/pam_rdp.py request --resource windows-rdp --ttl 120 \
  --credentials-file rdp/.local/requester.json
# Замените REQUEST_ID идентификатором из ответа.
python3 -B rdp/pam_rdp.py approve --request-id REQUEST_ID \
  --credentials-file rdp/.local/approver.json
# Теперь requester может открыть подключение в браузере.
python3 -B rdp/pam_rdp.py revoke --request-id REQUEST_ID \
  --credentials-file rdp/.local/approver.json
```

Вместо `approve` доступен `deny`. Самосогласование и повтор решения запрещены. CLI проверяет настоящую личность через Guacamole; `--actor` отсутствует. Пароли передаются через защищённые файлы. Служебная учётная запись имеет ADMINISTER: локальный оператор доверенный, это не изоляция от недоверенных пользователей ОС.

Записи хранятся в Docker-томе по идентификаторам истории и заявки. Guacd пишет, web-контейнер читает том; WORM нет. Копирование через буфер обмена, диски, передача файлов, печать и аудио отключены. Guacamole хранит пароль цели в своей БД; обычным пользователям он не выдаётся через API.

## Проверенный результат и границы

В лаборатории 8 сентября 2026 проверены: настоящее согласование и RDP-вход в Windows, уникальная надпись в Блокноте и тот же текст при воспроизведении полного файла записи, отзыв активного туннеля и запрет повторного подключения. В одном прогоне отзыв наблюдался за 0,2651 секунды — это измерение, не SLA. Отдельный тест с неверным отпечатком и без запасного доверия завершился отказом TLS до аутентификации. Проверены скрытие пароля и запрет чужого туннеля.

Воспроизведение проверялось по итоговому кадру полного потока, не по интерактивной временной шкале. Независимого чтения результата непосредственно с Windows не было. Завершение RDP не доказывает остановку фоновых процессов. Запись нужно читать после завершения её записи на диск.

При остановке обработчика или недоступности API истечение срока **не гарантировано**. При восстановлении/перезапуске оператор обязан закрыть пользовательский вход, выполнить `startup`, запустить обработчик и только затем вернуть доступ. Локальный признак готовности сам шлюз не закрывает.

Новый код этой папки распространяется под Apache-2.0; [лицензия](LICENSE) относится к нему. Лицензии сторонних компонентов сохраняются отдельно.
