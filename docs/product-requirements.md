# PAM: исходное ТЗ и границы поставки

Источник: архитектурная схема пользователя «Архитектура Open Source PAM-решения с логированием и аудитом», получена 2026-09-08. Схема задаёт целевую систему; наличие блока на ней не означает реализованную интеграцию.

## Целевой продукт

Единый контролируемый доступ администраторов к Linux, Windows, Kubernetes, базам данных и внутренним веб-приложениям. Вход через SSO и MFA, минимальные права, заявки и согласование временного доступа, отзыв, запись сессий и централизованный аудит.

| ID | Требование схемы | Компоненты-кандидаты | Приёмочное доказательство |
|---|---|---|---|
| PAM-01 | SSO и MFA, пользователи/группы | Authentik, AD/LDAP | Неверный issuer/audience, просроченный токен и отсутствие MFA отклоняются |
| PAM-02 | Запрос и согласование JIT | Access Workflow | Нельзя согласовать себе доступ; только разрешённый ресурс и ограниченный TTL |
| PAM-03 | Linux / Kubernetes / DB через шлюз | Teleport | Прямой сетевой доступ запрещён; просроченный и отозванный доступ отклоняются на ресурсе |
| PAM-04 | Windows / RDP / VNC через шлюз | Guacamole | Соединение только с IP шлюза; секрет не попадает клиенту и в логи |
| PAM-05 | Веб-приложения через reverse proxy | Authentik Outpost | Прямой обход заблокирован; проверяются SSO/MFA и права |
| PAM-06 | Секреты и временные credentials | Vault; OpenBao как отдельно оцениваемый вариант | Выдача ограничена политикой, TTL и отзывом; есть аудит обращения |
| PAM-07 | Запись сессий и хранение с retention | S3 Object Lock / MinIO-кандидат | Запись найдена по session ID; удалить её до retention нельзя |
| PAM-08 | Централизованные события и корреляция | Wazuh, OpenSearch | Заявка, решение, вход и сессия связаны; проверено оповещение |
| PAM-09 | Сегментация и отказоустойчивость | Сети управления/шлюзов/ресурсов; HA | Негативные сетевые тесты, отказ узла, восстановление резервной копии |

## Первый срез (лабораторный)

Исполняемый локальный workflow на Python/SQLite: заявка → независимое решение → проверка срока → отзыв/отказ и аудит переходов. CLI доверяет пользователю операционной системы: `actor` является лабораторным параметром, а не доказанной личностью. Сервис не выдаёт реальные сертификаты, пароли, сетевой доступ или сессии.

Этот срез проверяет часть PAM-02 и локальные события PAM-08. Он не закрывает PAM-01, PAM-03–07, PAM-09 или центральную доставку PAM-08. Для этих требований нужны отдельные адаптеры и интеграционный стенд. Статус «готово к промышленному применению» запрещён без соответствующих доказательств.

## Следующие поставки

1. Подтвердить редакции и лицензии компонентов, модель ролей, окружение развёртывания и SLO; решения фиксировать в architecture-review.md.
2. Один реальный маршрут доступа: Authentik → согласование → выбранный шлюз → тестовый Linux; проверка отказов и отзыва на целевом ресурсе.
3. Секреты и RDP, затем Kubernetes/DB и web. Каждый маршрут принимается отдельно по негативным тестам.
4. Внешний аудит, запись сессий, retention и доставка событий при отказах.
5. HA, восстановление, нагрузка, анализ зависимостей и внешняя проверка безопасности.

Стандарты служат основой будущей матрицы доказательств (NIST SSDF, OWASP ASVS для будущего веб-контура, ISO/IEC 25010 для качества). Соответствие и сертификация на первом срезе не заявляются.
