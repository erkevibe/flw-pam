# PAM: архитектурная проверка ТРИЗ-скептика

Проверено 8 сентября 2026 года по официальным документам. Ниже отделены подтвержденные возможности компонентов от предложений для следующих интеграционных срезов. Интеграционные тесты в этой записке — план, их выполнение здесь не заявляется. Наличие Compose-файла или ответ HTTP 200 не означает готовность PAM к эксплуатации.

## Ограничения исходных связей

### Teleport: редакция определяет SSO и условия распространения

В актуальной матрице Teleport для Community Edition в строке SSO указан GitHub; OIDC/SAML доступны в Enterprise. Поэтому связь Authentik → Teleport по OIDC нельзя считать штатной возможностью CE. Матрица также различает коммерческую лицензию готовых CE-бинарников с ограничениями и AGPL-3.0 для исходников GitHub. Для бесплатного корпоративного использования бинарников указаны одновременно менее 100 сотрудников и менее $10 млн годового дохода. Это сведения поставщика, а не заключение о применимости лицензии к конкретной организации. [Официальная матрица](https://goteleport.com/docs/feature-matrix/), [объявление об изменении лицензии начиная с v16](https://goteleport.com/blog/teleport-community-license/).

**Предложение СОВЕТу (pending):** Teleport вынести в необязательный профиль с явно выбранной редакцией. Для CE демонстрировать отдельно поддерживаемую локальную аутентификацию/настройку доступа; не рисовать завершенный общий OIDC-вход. Enterprise OIDC проверять только при доступной соответствующей редакции. Сборку исходников не считать способом автоматически получить Enterprise-возможности.

### Teleport и PostgreSQL: связь допустима, но это отдельный backend

Teleport документирует PostgreSQL для состояния кластера и audit events. Для state backend требуются logical decoding, `wal_level=logical`, replication slots с учетом количества Auth Service и необходимые права. Подключение должно идти прямо к PostgreSQL: PgBouncer несовместим с этим backend. Документация рекомендует TLS и проверку сертификата сервера. S3-хранилище session recordings — отдельная настройка; S3 не заменяет backend состояния. [Storage Backends: PostgreSQL и S3](https://goteleport.com/docs/reference/deployment/backends/).

**Предложение СОВЕТу (pending):** не включать Teleport backend в общую БД Guacamole/Authentik «по умолчанию». Сначала отдельные БД и пользователи; для Teleport профиль с собственной конфигурацией PostgreSQL и прямым соединением. Существование одного сервера PostgreSQL не доказывает изоляцию ролей и корректность replication. HA, failover и восстановление не заявлять без соответствующего опыта.

### Vault и OpenBao: не одинаковые лицензии и не проверенная взаимозаменяемость

В LICENSE Vault версии 1.15.0 и новее указан Business Source License 1.1 с Additional Use Grant и условиями. В LICENSE OpenBao указан MPL 2.0. Следовательно, весь набор нельзя безоговорочно описывать как единый permissive open-source стек. [Vault LICENSE](https://github.com/hashicorp/vault/blob/main/LICENSE), [OpenBao LICENSE](https://github.com/openbao/openbao/blob/main/LICENSE). Лицензия нашего репозитория не перелицензирует образы зависимостей.

**Предложение СОВЕТу (pending):** отдельно оценить OpenBao как альтернативу Vault для тестовых секретов; решение о замене Vault не принято; фиксировать версии и лицензии зависимостей. Не заявлять полную совместимость со всеми Vault-плагинами. Сначала проверять нужные API и lifecycle токенов на выбранной версии. Не писать собственное хранилище, шифрование, выдачу токенов или брокер поверх него.

### Guacamole: слово vault не означает HashiCorp Vault

Официальная документация Guacamole 1.6.0 прямо указывает, что vault extension сейчас поддерживает Keeper Secrets Manager. Она описывает KSM parameter tokens и KSM-конфигурацию; штатная интеграция с HashiCorp Vault или OpenBao этим документом не подтверждается. [Guacamole: Retrieving secrets from a vault](https://guacamole.apache.org/doc/gug/vault.html).

Guacamole отдельно предоставляет OIDC extension. Аутентификация пользователя и получение пароля целевой машины — разные интеграции, одну нельзя засчитывать за другую. [Guacamole: OpenID Connect](https://guacamole.apache.org/doc/gug/openid-auth.html).

**Предложение СОВЕТу (pending):** проверить Guacamole с OIDC и одним тестовым SSH/RDP-подключением. Динамическую выдачу целевых credentials из Vault оставить отдельным незавершенным пунктом. Если СОВЕТ отдельно выберет OpenBao, для конфигурационных секретов исследовать готовый OpenBao Agent: он умеет рендерить секреты в файлы и управляет их обновлением. Это не готовый Guacamole credential-injection plugin и не гарантия горячей ротации пароля подключения. [OpenBao Agent templates](https://openbao.org/docs/agent-and-proxy/agent/template/).

### MinIO WORM: защита версии объекта, редакция и сопровождение

Документация Object Lock различает GOVERNANCE, где специально уполномоченный клиент может обойти retention, и COMPLIANCE, где удержание защищает объект даже от root-пользователя S3 до истечения срока. Legal hold — отдельное состояние. Эти гарантии относятся к операциям хранилища; из них не следует невозможность уничтожить диск/volume администратором хоста. [Object Locking and Immutability](https://docs.min.io/aistor/administration/object-locking-and-immutability/).

На дату проверки официальный community-репозиторий MinIO архивирован и доступен только для чтения; GitHub указывает 25 апреля 2026 года. Ссылки старой Linux-документации перенаправляются в AIStor. Нельзя переносить актуальные обещания AIStor на любой старый community image. [Официальный репозиторий MinIO](https://github.com/minio/minio).

**Предложение СОВЕТу (pending):** если MinIO нужен для воспроизведения схемы, закрепить проверенный образ и явно обозначить его как лабораторный. Проверить retention и конкретный `versionId`, а не только upload. Выбор сопровождаемого S3/WORM-хранилища для дальнейшего применения — отдельное решение. Не включать длительный COMPLIANCE-retention на ценных данных ради теста; использовать выделенный тестовый bucket и короткий согласованный срок.

## Текущий первый срез

По [исходному ТЗ и границам поставки](/home/superuser/FLW/projects/flw-pam/docs/product-requirements.md) первый срез — локальный CLI workflow Python/SQLite: заявка, независимое решение, срок, отзыв/отказ и аудит переходов. Он не поднимает Guacamole/OIDC, не выдает реальные credentials и не открывает сетевой доступ. Поле actor — доверенный лабораторный параметр, а не подтвержденная личность. Проверяется часть PAM-02 и локальные события PAM-08; остальные интеграции не реализованы этим срезом.

## Следующий интеграционный срез: предложение СОВЕТу

В соответствии с очередностью ТЗ предлагается маршрут Authentik → согласование → выбранный шлюз → тестовый Linux с проверкой отказов и отзыва на ресурсе. Guacamole/OIDC — кандидат для отдельной проверки; выбор шлюза и редакции Teleport остается pending. Запись и воспроизведение сессии затем проверяются самостоятельным шагом. Vault остается компонентом исходной схемы; OpenBao — необязательная альтернатива, требующая отдельного решения СОВЕТа. Выдача/отзыв лабораторного секрета и S3 Object Lock проверяются отдельными контурами. Связи объединяются только после положительных интеграционных тестов. Teleport CE не должен изображать общий OIDC-контур, которого в выбранной редакции нет.

Главное противоречие ТРИЗ: хочется скрывать и ротировать все credentials, но новый универсальный брокер увеличивает число мест, где они раскрываются. Предлагаемое разрешение для интеграционных срезов — использовать готовые протоколы и агенты, сузить контур и оставить неподдержанную стрелку явно незавершенной. Собственная работа проекта: конфигурация, запуск, проверки, журнал доказательств и описание ограничений; новая система хранения/посредничества секретов сейчас не требуется.

## План интеграционных тестов

Все сценарии ниже пока имеют статус **planned**. Для каждого сохранять версии образов, команду/сценарий, время, фактический результат и обезличенные доказательства. Не помещать токены, пароли или содержимое приватных ключей в отчет.

| ID | Сценарий | Проверяемый результат |
| --- | --- | --- |
| IT-01 | Вход тестового пользователя через IdP в Guacamole и попытка чужого пользователя открыть соединение | Разрешенный вход работает; отсутствие права реально закрывает соединение, а не просто скрывает плитку |
| IT-02 | OIDC с неверным issuer/audience или недействительным токеном | Guacamole отклоняет вход; нет обхода через оставленную fallback-аутентификацию |
| IT-03 | Реальная SSH/RDP-сессия и playback | Действие на целевой машине выполнено; запись относится к этой сессии, пользователю и времени; playback читаем |
| IT-04 | Teleport выбранной редакции с PostgreSQL backend, затем перезапуск Auth | Состояние сохраняется; права и replication slots достаточны; неверный сертификат PostgreSQL отклоняется |
| IT-05 | Vault либо отдельно одобренный OpenBao: чтение разрешенного пути, запрет другого пути, отзыв токена | Разрешенный запрос проходит; чужой путь и отозванный токен отвергаются; проверка идет через настоящий API |
| IT-06 | Если отдельно выбран OpenBao и Agent templating: смена секрета и перезапуск/обновление потребителя | Зафиксированы фактическое время обновления и поведение приложения; старый secret не остается бессрочно рабочим |
| IT-07 | Upload новой записи в lock-enabled bucket с retention | Получены object key, versionId, retention mode и срок; содержимое совпадает с загруженной записью |
| IT-08 | Delete конкретной удерживаемой версии, overwrite того же key, обычный delete key | Версия под retention не удаляется; новая версия не подменяет доказательство старой; delete marker не принимается за исчезновение удерживаемой версии |
| IT-09 | GOVERNANCE с обычным клиентом и отдельно полномочием bypass; COMPLIANCE с администратором S3 | Разница режимов реально подтверждена на выбранном image; результат не обобщается на доступ администратора к файловой системе |
| IT-10 | Недоступность БД, выбранного Vault/OpenBao или S3 во время соответствующего действия | Нет ложной отметки «секрет получен»/«запись защищена»; ошибка наблюдаема, незавершенное действие отражено в отчете |

Успешные IT-01–IT-03 подтверждают только пользовательский лабораторный контур. IT-05 не подтверждает Guacamole↔Vault/OpenBao integration; IT-07 не подтверждает WORM без IT-08–IT-09. Сертификация, эксплуатационная готовность, HA/DR, долговременная ротация и единая политика прекращения сессий остаются за пределами первого среза.
