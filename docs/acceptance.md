Основание: `docs/product-requirements.md` и фиксированный `CONTRACT.md`.
Объект проверки — прототип локального согласования заявок на Python/SQLite.
`python3 -B -m unittest -q`: **29 тестов прошли**. GitHub Actions также проверяет

## Проверяемые границы

| Область | Негативные и граничные проверки | Ожидаемый результат |
|---|---|---|
| Личность | Пустые/нестроковые actor; самосогласование и самостоятельный отказ | ValueError, без изменений и новых событий |
| Доверенная граница | Переданный CLI actor | Лабораторный параметр доверенного OS-пользователя; не аутентификация |
| TTL | 0, -1, 3601, bool, float, NaN, infinity, строка; допустимые 1 и 3600 | Принимаются только int 1..3600, кроме bool |
| Часы | bool, NaN, infinity, отрицательное значение | Некорректное время отвергается |
| Срок | До, точно в и после expires_at; согласование после истечения | В точной границе доступ уже запрещён; согласование не продлевает срок |
| Ресурсы | Неизвестный ресурс; неверный allowlist; повторное открытие с иной политикой | Отказ; исходная политика хранится в БД |
| Переходы | pending/approved/denied/revoked; повторные approve/deny/revoke | Только разрешённые переходы, terminal состояния не восстанавливаются |
| Отзыв | Посторонний actor; requester/approver; отзыв после истечения | Посторонний отвергается; обе разрешённые стороны могут отозвать approved |
| Проверка | unknown id; несовпадающие ресурс и actor; expired; pending | Приоритет причин точно соответствует контракту, чтение не добавляет audit |
| Инъекции | Кавычки и SQL-фрагменты в допустимых строках | Значения остаются данными; таблицы и события сохраняются |
| Атомарность | Ошибка INSERT audit через SQLite trigger | Состояние заявки и событие откатываются вместе |
| Конкурентность | Два approver одновременно для одной заявки | Ровно один успех, одно событие approve, целостное состояние |
| Сохранность | Новые экземпляры Workflow для той же БД | Заявки, аудит и политика сохраняются |
| CLI | allowed/denied/error, JSON, повторные команды | Коды 0/1/2 и документированный формат; импорт без побочных эффектов |

## Ограничения приёмки

Перечисленные unit-проверки согласования закрывают только лабораторную часть PAM-02 и локальный
аудит PAM-08. Они не доказывают SSO/MFA, проверенную личность, выдачу реального
доступа, отзыв на целевом ресурсе, запись сессии, защищённое хранение секретов,
WORM/retention, централизованную доставку событий, сетевую сегментацию или HA.
Владелец SQLite/ОС может менять данные: локальный audit не защищён от него.
Источник времени также доверенный: перевод системных часов назад может снова
сделать ещё не отозванную заявку действующей по сроку. Проверки с подставными
часами подтверждают формулу границы, но не защищённость часов от изменений.
Промышленная готовность и сертификация не заявляются.


## SSH-шлюз: реальная интеграционная проверка

8 сентября 2026 на свежем локальном Docker-стенде прошли 29 unit-тестов,
`tests/integration_gateway.py --static` и `--live`. Образы Guacamole/guacd 1.6.0,
PostgreSQL 16, тестовый SSH-сервер на Debian bookworm; Docker Engine 29.6.2.

Проверены вход обычного пользователя, отказ при неверном и стандартном пароле
администратора, отказ подключения пользователю без прав, подлинный HTTP-туннель
Guacamole и выполнение уникальной команды на Linux. Результат команды независимо
прочитан на целевом сервере. Новая запись этой сессии содержит 33788 байт и
60 инструкций протокола; два sync совпали с проверенным туннелем.
Проверены закреплённый SSH host key и права чтения/записи каталога записей.

Веб-порт опубликован только на `127.0.0.1:8080`; отдельная frontend-сеть
подключена только к web. PostgreSQL, guacd и SSH не публикуют порты,
control/target — внутренние сети. Это конфигурация лаборатории,
а не доказательство защиты от администратора Docker или ОС.

Остались непроверенными SSO/MFA, связанное с workflow ограничение доступа по
сроку и отзыв, RDP/VNC, WORM/retention, HA и промышленная эксплуатация.
Веб-воспроизведение записи отдельно не проверялось: интеграционный тест проверяет
сам протокол записи и его связь с сессией. GitHub Actions содержит отдельный
реальный Docker job; его результат смотрите во вкладке Actions.
