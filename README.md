# PAM — управление привилегированным доступом

Цель проекта — система доступа администраторов к Linux, Windows, Kubernetes, базам данных и внутренним веб-приложениям: SSO/MFA, временные права, согласование, запись сессий и аудит.

## Текущее состояние

**Полная PAM-система ещё не готова.** Проверены два локальных стенда: SSH-доступ к тестовому Linux и новый Windows/RDP-сценарий с настоящим согласованием, записью действия и отзывом живого туннеля. [Запуск Windows/RDP и ограничения](rdp/README.md).

**Два незакрытых дефекта RDP:** просроченное право может сохраняться при остановленном обработчике; стартовая очистка не блокирует вход на шлюз автоматически. SSO/MFA и WORM ещё не подключены.

Старый `workflow.py` остаётся отдельным Python/SQLite-прототипом с доверенным `--actor`; он не управляет шлюзом. Новый `rdp/pam_rdp.py` аутентифицирует участников через Guacamole и изменяет настоящие права подключения.

## Целевая архитектура

| Задача | Компоненты из ТЗ | Статус |
|---|---|---|
| SSO и MFA | Authentik | Не интегрировано |
| Секреты и временные credentials | Vault | Не интегрировано |
| SSH, Kubernetes, DB | Teleport | Не интегрировано; требуется выбор редакции |
| RDP / VNC / SSH в браузере | Guacamole | SSH и Windows/RDP со связанным согласованием, записью и отзывом; VNC не проверен |
| Доступ к веб-приложениям | Authentik Outpost | Не интегрировано |
| Логи, корреляция и хранение записей | Wazuh, OpenSearch, S3/WORM | Не интегрировано |
| Согласование заявок | Native Guacamole + Python/SQLite | Реальные API и Windows/RDP проверены с указанными ограничениями |

## Запуск SSH-стенда

Linux, Python 3.11+, Docker Engine и Docker Compose. Из корня репозитория:

```sh
python3 lab/bootstrap.py prepare
docker compose --env-file lab/.local/.env up -d --build
python3 lab/bootstrap.py provision
python3 tests/integration_gateway.py --live
```

Откройте [Guacamole на этом компьютере](http://127.0.0.1:8080/guacamole/). Пользователь `pam-user`, пароль — значение `GUAC_PASSWORD` в локальном `lab/.local/.env`. Выберите **PAM lab SSH**. Пароли создаются при подготовке и не входят в репозиторий. Завершайте настройку командой `provision` перед использованием: она меняет стандартный пароль администратора.

Интеграционный тест входит через настоящий HTTP-туннель Guacamole, выполняет уникальную команду на SSH-сервере, независимо проверяет результат и запись этой сессии. Также проверяются отказ при неверном пароле и запрет подключения пользователю без прав. Недоступный Docker и ошибки дают ненулевой код, без пропуска теста.

[Подробный запуск, остановка и хранение данных](lab/README.md) · [Устройство шлюза](docs/gateway.md). Это лаборатория с локальным HTTP и тестовым Linux: SSO/MFA, Vault, временные права и защищённое хранение записей ещё не подключены.

## Запуск прототипа согласования

Python 3.11+, без внешних зависимостей. Команды выполняются из корня репозитория.

```sh
python3 -B -m unittest discover -v
python3 workflow.py --help
python3 workflow.py --db /tmp/pam-demo.db request --actor alice --resource db-read --reason demo --ttl 300
# Подставьте id из результата первой команды:
python3 workflow.py --db /tmp/pam-demo.db approve REQUEST_ID --actor bob
python3 workflow.py --db /tmp/pam-demo.db check REQUEST_ID --actor alice --resource db-read
python3 workflow.py --db /tmp/pam-demo.db revoke REQUEST_ID --actor alice --reason done
python3 workflow.py --db /tmp/pam-demo.db audit
```

[API прототипа](CONTRACT.md). Проверка доступа возвращает код 0 при разрешении, 1 при отказе; ошибочный ввод — 2. TTL ограничен 1–3600 секундами. Согласование не продлевает срок.

## Следующий результат разработки

Закрыть два дефекта принудительного ограничения доступа: истечение срока при остановленном обработчике и запрет входа до завершения стартовой очистки. Затем подключать SSO/MFA и защищённое хранение записей. Работающий Windows-сценарий не заменяет эти проверки безопасности.
